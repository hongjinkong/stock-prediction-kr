## 📖 이게 대체 무슨 프로젝트인가요?

### 처음 생각 — "미래를 맞히면 되잖아?"

주식으로 돈 버는 법은 간단해 보입니다. **오를 걸 미리 알면 됩니다.**
요즘은 AI가 좋으니까, AI한테 과거 주가를 잔뜩 먹이면 내일을 맞히지 않을까?

그래서 이 프로젝트는 거기서 시작했습니다. 딥러닝 모델을 만들고, 과거 데이터로 테스트했더니
**성능이 잘 나왔습니다.** 신났죠.

### 그런데 함정이 있었습니다

테스트를 다시 꼼꼼히 뜯어보니 두 가지 문제가 있었습니다.

**함정 1 — 데이터 누출 (look-ahead bias)**

> 🎓 시험 문제를 풀기 전에 **답안지를 몰래 본 것**과 같습니다.
>
> 예를 들어 "빈칸을 앞뒤 값으로 채우기" 같은 흔한 데이터 정리 기법이 있는데,
> 이걸 시계열 데이터에 쓰면 **내일 값이 오늘 칸에 흘러들어옵니다.**
> 모델은 미래를 보고 답을 맞힌 건데, 우리는 "우리 AI 똑똑하다"고 착각합니다.
> 실전에서는 내일 값이 당연히 없으니 그대로 무너집니다.

**함정 2 — 과적합 (overfitting)**

> 🎓 **기출문제만 통째로 외운 학생**과 같습니다.
>
> 과거 데이터에 딱 맞는 설정을 찾을 때까지 계속 바꿔보면, 결국 아주 잘 맞는 조합이 나옵니다.
> 근데 그건 실력이 아니라 **답을 외운 것**입니다. 새로운 시험(=미래 시장)에서는 무너집니다.

### 함정을 다 제거했더니 — 성능이 사라졌습니다

누출을 막고, 하이퍼파라미터를 고를 때 테스트 구간을 완전히 격리하고,
거래 수수료까지 반영했더니 — **정확도가 52%로 내려앉았습니다.** 동전던지기가 50%입니다.

같은 모델을 5개 종목에 똑같이 돌려봤더니:

| 종목 | 맞힌 정도 (AUC) | 해석 |
|---|---|---|
| AAPL (애플) | 0.601 | 조금 나음 |
| NVDA (엔비디아) | 0.554 | 살짝 나음 |
| TSLA (테슬라) | 0.500 | **정확히 동전던지기** |
| JPM (JP모건) | 0.498 | 동전던지기 |
| MSFT (마이크로소프트) | 0.485 | 동전던지기보다 못함 |
| **평균** | **0.527** | 5개 중 3개가 무작위 수준 |

> 🎓 **AUC**: 0.5 = 완전 무작위(동전던지기), 1.0 = 완벽. 0.527은 "거의 못 맞힌다"는 뜻입니다.

**이건 실패가 아니라 발견입니다.** 무료로 구할 수 있는 데이터로 대형주 방향을 맞히는 건
개인에겐 사실상 불가능하다 — 시장이 그만큼 효율적이라는 뜻입니다.
그리고 이 사실을 알았기 때문에, **가짜 성능을 믿고 실제 돈을 넣는 사고를 막았습니다.**

### 그래서 문제를 바꿨습니다

> ❌ **"내일 오를까?"** — 못 맞힘. 포기.
> ✅ **"지금 오르는 중인가?"** — 이건 그냥 보면 압니다. 예측이 아니라 **관찰**입니다.

이 시스템은 미래를 맞히지 않습니다. **이미 벌어진 일에 반응만 합니다.**
오르는 중이면 들고 있고, 꺾이면 팝니다. 그게 전부입니다.

그런데 이게 **폭락을 피하는 데는 실제로 작동합니다.**

### ⚠️ 꼭 알아둘 3가지

| 상황 | 왜 그런가 / 어떻게 하나 |
|---|---|
| **터미널 창을 닫으면 사이트도 꺼집니다** | 이 터미널이 곧 서버입니다. 사이트를 보는 동안은 창을 열어두세요. 끄려면 `Ctrl+C`. |

## 🧠 실제로 쓴 모델들 — 쉬운 설명

### A. 실패한 쪽: AI 예측 모델 (`notebooks/prediction/`)

**목표**: 3일 뒤에 오를지 내릴지 맞히기. 세 모델을 섞어서(앙상블) 썼습니다.

| 모델 | 한 줄 설명 | 비유 |
|---|---|---|
| **PatchTST** (딥러닝) | 시계열을 짧은 토막(patch)으로 잘라, 토막들 사이의 관계를 학습하는 트랜스포머 | ChatGPT가 문장을 단어 단위로 읽듯, **주가를 며칠 단위 토막으로 읽는** 모델 |
| **LightGBM** | "이 조건이면 위, 아니면 아래" 하는 결정 트리를 수천 개 쌓아 조금씩 오답을 고쳐나감 | **스무고개를 수천 번** 반복해서 정답에 다가가기 |
| **RandomForest** | 서로 다른 트리 수백 개를 각자 학습시키고 **다수결** | **전문가 수백 명한테 각자 물어보고 투표** |

**입력한 것**: 일봉 시가/고가/저가/종가/거래량 + 기술지표(이동평균, RSI, MACD 등) + 거시경제 지표

**결과**: ❌ 평균 AUC 0.527. 못 맞힙니다.

**왜 실패했나** — 이건 모델이 나빠서가 아닙니다. **그런 정보가 가격에 이미 다 들어있어서**입니다.
누구나 볼 수 있는 데이터로 알 수 있는 건, 이미 다른 사람들이 다 반영해버렸습니다.

### B. 채택한 쪽: 추세추종 시스템 (`trend_system/`) ⭐

**AI가 아닙니다. 머신러닝이 아닙니다.** 규칙 4개가 전부입니다.
바로 그래서 **믿을 수 있습니다** — 학습할 게 없으면 과적합할 것도 없습니다.

#### 규칙 1️⃣ — 오르는 중인 것만 산다 (추세 필터)

```
오늘 종가 > 최근 200일 평균 가격  →  🟢 상승추세, 보유
오늘 종가 < 최근 200일 평균 가격  →  🔴 하락추세, 현금
```

> 🎓 **200일 이동평균**: 최근 200일 종가를 평균 낸 값. 매일 새로 계산되니까 선처럼 움직입니다.
> 가격이 이 선 위에 있으면 "요즘 잘나가는 중", 아래면 "요즘 시들한 중"이라는 뜻입니다.
>
> **왜 200일인가?** 특별히 좋아서가 아닙니다. **수십 년간 쓰여온 관습값**이라서입니다.
> 이 데이터에 맞춰 "제일 좋은 숫자"를 골랐다면 그게 바로 과적합입니다. 일부러 안 골랐습니다.

#### 규칙 2️⃣ — 많이 흔들리는 것엔 적게 넣는다 (역변동성 배분)

```
비중 = 3% ÷ 그 종목의 연간 변동성     (최대 30% 상한)
```

> 🎓 **변동성**: 가격이 얼마나 널뛰는지. 변동성 40%면 "1년에 ±40% 정도는 흔들린다"는 뜻입니다.

실제 계산 예시:

| 종목 | 변동성 | 계산 | 비중 |
|---|---:|---|---:|
| SPY | 14% | 3% ÷ 14% | **22%** |
| MSFT | 45% | 3% ÷ 45% | **6.6%** |

**왜?** 각 종목이 포트폴리오 전체에 주는 **위험의 크기를 똑같이 맞추기** 위해서입니다.
사나운 종목을 적게 담으면, 그 종목이 폭락해도 전체가 받는 충격은 순한 종목과 비슷해집니다.

> 🍳 요리로 치면, 맵기가 다른 재료를 **같은 매운맛이 되도록** 양을 조절하는 것과 같습니다.
> 청양고추는 조금, 파프리카는 많이.

#### 규칙 3️⃣ — 빚내서 사지 않는다

전부 더해서 100%를 넘으면 비례로 줄입니다. **레버리지 금지.**
추세가 켜진 종목이 적으면 나머지는 그냥 현금으로 둡니다 (현재 19.9%가 현금).

#### 규칙 4️⃣ — 한 달에 한 번만 손댄다 (+ 3% 밴드)

- **21영업일(약 한 달)에 한 번**만 비중을 다시 맞춥니다
- 그때도 **차이가 3% 미만이면 그냥 놔둡니다** — 수수료 아끼려고
- 단, **추세가 꺼진 종목 청산은 무조건** 실행합니다

> 🎓 매매할 때마다 수수료가 나갑니다. 매일 조금씩 고치면 수수료로 수익이 다 녹습니다.
> 이 시스템은 16년 동안 원금의 **39.8배**만큼만 거래했습니다(연 2.4회전 수준 = 아주 낮음).

#### 📅 그래서 매달 이런 식으로 돌아갑니다

```
   시세 받기 (yfinance)
        ↓
   9개 자산 각각: 200일선 위인가?     →  🟢 7개    🔴 2개 (TLT, GLD)
        ↓
   🟢인 것만: 3% ÷ 변동성 으로 비중 계산
        ↓
   합이 100% 넘으면 비례 축소 / 종목당 30% 상한
        ↓
   현재 보유와 비교 → 차이 3% 넘는 것만 주문 생성
        ↓
   📋 "SPY 22%, JPM 12.8%, ... 현금 19.9%"  +  주문 목록 CSV
```

#### 💰 다루는 9개 자산

성격이 다른 것들을 일부러 섞었습니다. 하나가 무너질 때 다른 게 버텨주도록.

| 종류 | 종목 | 역할 |
|---|---|---|
| **지수 ETF** | SPY(S&P 500), QQQ(나스닥100) | 미국 시장 전체 |
| **개별주** | AAPL, MSFT, NVDA, JPM, XOM | 기술·금융·에너지 |
| **안전자산** | GLD(금), TLT(미국 장기국채) | 주식이 빠질 때 버텨주는 것 |

## 🔍 정직한 검증 — 내 결과를 내가 공격했습니다

여기가 이 프로젝트의 **진짜 핵심**입니다.

백테스트 결과가 좋게 나오면 기분이 좋습니다. 근데 좋은 숫자는 **거의 항상 어딘가 속임수가 있습니다.**
그래서 스스로를 공격하는 검사 6가지를 만들었습니다. 전부 `scripts/validate.py`로 재현 가능하고,
결과는 대시보드 "검증" 탭에 그대로 공개돼 있습니다.

### 검사 1 — 백테스트 가정이 현실적인가?

옛날 버전은 "**매일 무료로 비중을 완벽히 맞춘다**"고 가정하고 있었습니다. 현실엔 불가능합니다.
현실적으로 고쳤습니다: 리밸런싱 사이엔 비중이 가격 따라 흘러가고(드리프트), 현금엔 이자가 붙고, 3% 밴드를 적용.

| | 최대낙폭 |
|---|---|
| 낙관 가정 (옛 버전) | −15.7% |
| **현실 가정 (현재)** | **−16.9%** |

→ 숫자가 나빠졌지만, **이게 진짜입니다.** 나쁜 쪽이 정직한 쪽입니다.

### 검사 2 — 비교 대상이 공정한가? ⭐ 가장 중요

많은 백테스트가 **S&P 500과 비교**해서 "우리가 이겼다"고 합니다. 하지만 이건 반칙입니다.
이 시스템은 엔비디아·애플 같은 개별주도 담고 있으니까요.

**공정한 비교 대상은 "똑같은 9개 자산을 그냥 균등하게 사서 들고 있기"입니다.**

| 지표 | 🧺 추세추종 | 📦 같은 9자산 균등보유 | 📊 S&P 500 | ⚖️ 60/40 |
|---|---|---|---|---|
| 연평균 수익률 (CAGR) | 14.7% | **19.7%** | 14.1% | 10.1% |
| 변동성 | **10.9%** | 16.0% | 17.1% | 10.3% |
| 위험 대비 수익 (Sharpe) | **1.19** | 1.12 | 0.78 | 0.86 |
| **최대낙폭 (MDD)** | **−16.9%** | −26.7% | −33.7% | −27.2% |

**정직하게 말하면:**
- 📉 **수익률로는 졌습니다.** 균등보유가 19.7% vs 이 시스템 14.7%
- 📊 위험 대비로는 조금 낫지만(1.19 vs 1.12), **이 차이는 통계적으로 무의미합니다**

> 🎓 부트스트랩 검정 2,000회를 돌려봤습니다. **p = 0.681**, 신뢰구간 [−0.23, +0.36].
> 쉽게 말하면: **"이 차이는 그냥 운일 가능성이 매우 높다."** 우연히 이 정도 차이는 흔히 납니다.
> → **"이게 더 낫다"고 주장할 수 없습니다.**

- ✅ **재현 가능한 진짜 효과는 딱 하나 — 낙폭이 약 10%p 작다는 것**

### 검사 3 — 리밸런싱 날짜를 잘 고른 건 아닌가?

"한 달에 한 번" 리밸런싱한다면, **시작을 며칟날로 잡느냐**에 따라 21가지 경우가 나옵니다.
21개를 전부 돌려봤습니다.

| | Sharpe | 최대낙폭 |
|---|---|---|
| 발표한 숫자 (1번 경우) | **1.19** | **−16.9%** |
| 21개 평균 | 1.08 | −20.5% |
| 21개 중 최악 | 0.99 | **−23.0%** |

**발표한 숫자는 21개 중 제일 예쁜 하나였습니다.** 정직하게는 **평균 −20.5%, 최악 −23.0%**로 봐야 합니다.

### 검사 4 — 종목을 결과 알고 고른 건 아닌가?

애플·엔비디아·마이크로소프트를 2026년에 앉아서 고르는 건 반칙입니다. **다 오른 걸 이미 아니까요.**
개별주를 빼고 ETF 4개(SPY·QQQ·GLD·TLT)만으로 돌려봤습니다.

| | CAGR | Sharpe | 최대낙폭 |
|---|---|---|---|
| 9자산 (개별주 포함) | 14.7% | 1.19 | −16.9% |
| **ETF만 4개** | **7.7%** | **0.99** | **−8.4%** |

→ **수익의 약 47%가 종목 선택에서 왔습니다.** 이 부분은 **미래에 재현된다는 보장이 전혀 없습니다.**
→ 하지만 ETF만 써도 **Sharpe 0.99, 낙폭 −8.4%**. **리스크 관리 효과 자체는 종목 선택과 무관하게 남습니다.**

### 검사 5 — 파라미터를 유리하게 고른 건 아닌가?

"200일선은 관습값이라 과적합이 아니다"라고 주장하려면, **증명해야** 말이 됩니다.
파라미터 조합 36개를 전수 실행했습니다 (추세창 4가지 × 변동성창 3가지 × 위험비중 3가지).

| | 결과 |
|---|---|
| 36개 조합의 Sharpe 범위 | 1.07 ~ 1.28 (좁게 뭉쳐 있음) |
| **기본값(200/63/3%)의 순위** | **19위 / 36개 — 딱 한가운데** |
| 36개 전부 플러스인가? | ✅ 예 |

→ 기본값이 **봉우리가 아니라 한가운데**입니다. 어떤 값을 골라도 비슷하게 나옵니다.
→ **파라미터를 고른 행위가 성과를 만든 게 아니라는 뜻 = 과적합이 아닙니다.**

> 🎓 과적합된 전략은 반대로 나옵니다. 특정 값에서만 성과가 튀고 조금만 바꿔도 무너집니다.
> 그게 **"이 데이터에만 맞춰졌다"**는 신호입니다.

### 검사 6 — 폭락 때 실제로 막아줬나? (존재 이유)

| 위기 | 🧺 추세추종 | 📦 균등보유 | 📊 S&P 500 |
|---|---|---|---|
| 2011 미국 신용등급 강등 | **+7.0%** | +4.8% | −4.4% |
| 2015-16 차이나 쇼크 | −5.9% | **+4.2%** | −7.0% |
| 2018 Q4 급락 | **−10.8%** | −17.1% | −13.5% |
| **2020 코로나 폭락** | **−14.0%** | −25.7% | **−33.4%** |
| **2022 금리인상 약세장** | **−6.7%** | −23.3% | −24.1% |

→ **5번 중 4번 방어에 성공했습니다.** 특히 2020·2022 같은 큰 하락장에서 차이가 확실합니다.
→ 2015-16년엔 오히려 졌습니다 — 짧게 빠졌다 바로 회복하는 장에서는 **팔았다가 다시 사느라 손해**를 봅니다.
   이게 추세추종의 대표적 약점입니다.

### 📌 6가지 검사의 결론

> ### 이건 "더 버는 법"이 아니라 **"덜 잃는 법"**입니다.
>
> - ❌ 수익률 우위 — **주장할 수 없습니다** (p=0.681)
> - ❌ 개별주 성과 — **미래 재현 보장 없습니다** (후견편향)
> - ✅ 낙폭 축소 약 10%p — **이것만이 재현 가능한 효과입니다**
>
> 이 시스템의 값어치는 **폭락장에서 덜 잃고 살아남아 다음 상승장에 참여하는 것**입니다.

| 하고 싶은 것 | 명령어 |
|---|---|
| 🌐 **웹 대시보드 띄우기** (제일 많이 씀) | `.venv/bin/python scripts/serve.py` |
| 🔍 검증 리포트 (위 6가지 검사) | `.venv/bin/python scripts/validate.py --cache` |
| 📋 이번 달 목표 비중·주문 리포트 | `.venv/bin/python scripts/advisory.py --nav 10000` |
| 🔄 대시보드 데이터만 다시 만들기 | `.venv/bin/python scripts/build_site.py --cache` |
| 👀 모의매매 미리보기 (주문 안 냄) | `.venv/bin/python scripts/paper_trade.py` |
| ✅ 모의계좌에 실제 주문 | `.venv/bin/python scripts/paper_trade.py --execute` |
| 📈 성과 추적 (vs 시장) | `.venv/bin/python scripts/monitor.py` |

> 🎓 `--cache`: 시세를 로컬에 저장해두고 재사용합니다. 두 번째부터 훨씬 빠릅니다.
> `--nav 10000`: 계좌에 $10,000 있다고 가정.

### (선택) API 키 설정

모의 자동매매를 쓰려면 `.env.example`을 복사해 `.env`로 만들고 채웁니다.

```
ALPACA_API_KEY_ID=...          # alpaca.markets 모의계좌 키 (무료)
ALPACA_API_SECRET_KEY=...
SEC_USER_AGENT=이름 이메일       # SEC 재무 데이터 접근용
```

> 🔒 `.env`는 git에 **절대 올라가지 않습니다.** 실제 키를 `.env.example`에 쓰지 마세요.

## 📖 용어 사전 (economics + coding)

### 💰 경제·투자 용어

| 용어 | 쉬운 뜻 |
|---|---|
| **백테스트** | 과거 데이터로 "이 전략을 그때 썼으면 어땠을까"를 돌려보는 것 |
| **CAGR (연평균 수익률)** | 여러 해 수익을 "매년 몇 %씩 불었나"로 환산한 값 |
| **변동성 (Volatility)** | 가격이 얼마나 널뛰는지. 40%면 1년에 ±40% 정도 흔들린다는 뜻 |
| **MDD (최대낙폭)** | **가장 중요.** 고점 대비 최대로 까였던 폭. −33%면 1억이 6,700만이 됐다는 뜻 |
| **Sharpe 비율** | "위험 1만큼 감수해서 수익 얼마나 얻었나". 1 넘으면 괜찮은 편 |
| **이동평균 (SMA)** | 최근 N일 가격의 평균. 200일 이동평균 = 최근 200일 평균가 |
| **리밸런싱** | 비중이 틀어진 걸 목표대로 다시 맞추는 것 |
| **레버리지** | 빚내서 투자하기. 이 시스템은 **안 씁니다** |
| **ETF** | 여러 종목을 한 바구니에 담아 주식처럼 사고파는 상품 (SPY = S&P 500 한 방에) |
| **유니버스** | 전략이 다루는 종목 목록 (여기선 9개) |
| **알파** | 시장 수익을 넘어서는 초과 수익. **이 프로젝트는 못 찾았습니다** |
| **롱 / 숏** | 롱 = 사서 오르면 이득 / 숏 = 빌려 팔아 내리면 이득. 이 시스템은 **롱 아니면 현금**만 |
| **60/40** | 주식 60% + 채권 40%의 전통적 기본 배분 |
| **후견편향** | 결과를 이미 알고 나서 "그때 이걸 샀어야지" 하는 것. 백테스트의 대표적 함정 |

## 💡 이 프로젝트에서 배운 것

1. **데이터 누출을 제거하면 "고성능"의 대부분이 사라진다** — 엄격함이 자기기만을 막는 최고의 무기
2. **일봉 기술지표로 대형주 방향 예측 = 알파 없음** — 시장이 그만큼 효율적이다
3. **정확한 예측 ≠ 돈이 되는 예측** — 예측되는 것(변동성)조차 단순한 방법이 이미 가치를 다 담고 있으면 무의미
4. **예측 실패 ≠ 프로젝트 실패** — 리스크 관리로 전환한 것이 정직하고 견고한 답
5. **진짜 엣지는 더 좋은 모델이 아니라 다른 데이터·다른 문제에 있다** — 남들이 못 보는 데이터, 덜 붐비는 시장
6. **좋은 숫자가 나오면 의심해라** — 검증 6가지를 만들고 나니, 자랑하던 −16.9%가 사실 −20.5%였다
